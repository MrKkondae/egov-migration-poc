# package-scan-analysis.md 검토 프롬프트

너는 전자정부프레임워크 3.x → 4.3 전환 분석 프롬프트 품질 검토 전문가다.

## 목표

`prompt/qwen/analysis/package-scan-analysis.md` 파일을 검토하여, Qwen이 전자정부프레임워크 3.x 프로젝트의 Java 패키지 구조를 정확히 분석하고 4.3 전환 작업에 필요한 정보를 안정적으로 도출할 수 있는지 확인한다.

이 작업에서는 절대 소스코드나 프롬프트 파일을 수정하지 않는다.  
검토 결과와 보완 제안만 작성한다.

## 검토 대상 파일

- `prompt/qwen/analysis/package-scan-analysis.md`

## 검토 관점

다음 항목을 기준으로 검토한다.

### 1. 분석 목적의 명확성

- 이 프롬프트가 “패키지 구조 분석”을 목적으로 한다는 점이 명확한가?
- 전자정부프레임워크 3.x → 4.3 전환 관점에서 왜 패키지 분석이 필요한지 설명되어 있는가?
- 단순 목록화가 아니라 이후 DAO / Service / Controller / XML 분석과 연결될 수 있는가?

### 2. 분석 범위 적정성

다음 항목을 충분히 분석하도록 되어 있는지 확인한다.

- Java package 선언 기준 패키지 목록
- 디렉토리 구조와 package 선언 불일치 여부
- 업무 도메인별 패키지 구분
- 공통 / 기반 / util / cmm / cmmn / common 패키지 식별
- Controller / Service / DAO / VO / DTO / Mapper / Scheduler / Batch 등 계층별 패키지 식별
- egovframework 관련 패키지 사용 여부
- 전자정부프레임워크 표준 구조와의 차이
- 4.3 전환 시 우선 분석해야 할 패키지
- 폐기 가능성 또는 미사용 가능성이 있는 패키지 후보

### 3. 전자정부프레임워크 4.3 전환 관점 반영 여부

다음 전환 포인트가 반영되어 있는지 검토한다.

- eGovFrame 3.x 기반 패키지 구조와 4.3 기준 구조 차이
- Spring MVC / Spring Bean / MyBatis / iBATIS 사용 가능성
- `egovframework.rte.*` 사용 위치 파악 필요성
- 업무 패키지와 프레임워크/공통 패키지 분리 필요성
- 향후 javax → jakarta 변경 여부 판단을 위한 기초 정보 수집 가능성
- XML bean 설정 분석과 Java 패키지 구조 분석의 연결 가능성

### 4. Qwen 실행 안정성

- 지시사항이 모호하지 않은가?
- Qwen이 소스 수정 없이 분석만 수행하도록 충분히 통제되어 있는가?
- 추측, 임의 판단, 할루시네이션을 방지하는 규칙이 있는가?
- 실제 확인한 파일/패키지 기준으로만 결과를 작성하도록 되어 있는가?
- 확인 불가 항목은 “확인 불가”로 표시하도록 되어 있는가?

### 5. 출력 형식 적정성

출력 결과가 이후 작업에 재사용 가능하도록 되어 있는지 검토한다.

다음과 같은 출력 항목이 포함되어야 한다.

- 전체 패키지 요약
- 계층별 패키지 분류
- 업무 도메인별 패키지 분류
- 공통/기반 패키지 목록
- 전자정부프레임워크 관련 패키지 목록
- 패키지별 주요 클래스 예시
- 전환 위험 패키지
- 후속 분석 대상 패키지
- 확인 불가 또는 추가 확인 필요 항목
- 최종 요약

### 6. 다른 분석 프롬프트와의 연계성

다음 분석 프롬프트들과 역할이 중복되거나 누락되지 않는지 검토한다.

- dao-analysis.md
- sqlmap-analysis.md
- spring-context-analysis.md
- controller-analysis.md
- service-analysis.md
- batch-analysis.md

특히 package-scan-analysis.md는 상세 변환 지시가 아니라 “전체 구조 파악 및 후속 분석 대상 식별”에 집중해야 한다.
